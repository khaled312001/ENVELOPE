This is not a build from zero. The calculation engine exists, is tested, and already reads the three real affection plans you supplied and reproduces the figures printed on them exactly. The week buys the product around it: the screens, the drawings, the exports, the database and the deployment.

The one thing that separates it from a spreadsheet

Every figure the system prints can say where it came from. If a clause of the code governs it, the clause reference and page number travel with the number. If no clause governs it, the system does not quietly pick a value — it marks the figure assumed, in amber, states the basis it assumed on, and measures how far the answer moves if that assumption is wrong.

Why that matters commercially

A number you cannot source is a number you have to re-derive by hand before you can put your name on it. The whole value of the tool is that it hands you work you can check in minutes instead of work you have to repeat.

The insight the product is built on

Unit count is not set by FAR alone. It is set by the smaller of two numbers: what the GFA permits, and what the parking can actually serve. On most Dubai plots the parking binds. So a system that can lay out parking correctly knows the unit count — not the other way round. That is why the parking layout, not the massing, is the centre of this build.

What is delivered

A ten-step web application. Read it as the scope of work: what is not on this page is not included.

  • Affection plan upload and automatic reading. Area, FAR, GFA, height, setbacks and coverage extracted from the PDF, each one shown at its position on the sheet so you can verify it. The system re-checks the sheet against itself: FAR × area must reproduce the printed GFA, and it tells you when it does not.
  • Plot drawing by dimensions, and edge classification. Enter side lengths; mark each edge as road, neighbour or open space — which determines the setback and where the entrance may go.
  • Buildable envelope. Podium and tower footprints, setback lines, level count and achieved GFA — each naming the constraint that produced it and by how much the next one missed.
  • Parking laid out as real geometry — the core of the build. Not an area divided by a factor. Bays, aisles and the ramp are placed as rectangles at Dubai Building Code Table B.11 dimensions — 2.5 × 5.5 m bays, 6.00 m two-way driveway — inside the actual podium outline, with the m²-per-bay efficiency reported. A bay count that cannot be laid out is not a bay count. Ramp gradient and headroom are checked against B.7.2.2, from the ramp run and the floor-to-floor height.
  • Vehicle entrance recommendation. Per clause B.7.2.1: on a road edge, 6 m wide, 15 m clear of each corner, secondary road preferred. Every viable alternative is ranked, with the reason each rejected one was rejected — the decision stays yours.
  • Unit mix and unit count, with the governing limit named. Compares what the GFA permits against what the parking supports, takes the smaller, and states which of the two bound the answer and by what margin.
  • 3D massing view with live parameter editing. The envelope stood up in the browser, no software to install. Change a parameter and the numbers recompute immediately.
  • Six exports, including IFC into Revit. DXF on named layers · IFC 4 (ISO 16739), which Revit imports natively · glTF massing for any 3D viewer · Excel with area, unit, parking and assumption schedules · a PDF report with references · JSON, so any run re-runs months later to the identical result. All six are written against published formats; none needs a paid subscription.
  • Coded Dubai Building Code clauses. Parking ratios, bay and aisle dimensions, access and ramp rules, and setbacks — each a dated record with its reference and page number, not a condition hidden in code.
  • One developer standard (Azizi) as the working model. Unit-area caps, saleable efficiency and parking targets, transcribed with the page and position each came from — built so adding Emaar or Damac later is data entry, not programming.
  • MySQL database, server deployment, and full source code ownership. Deployed on your hosting, handed over complete.

What it does not do

The section worth reading twice. Everything here is something that would otherwise be assumed to be included.

  • It does not certify compliance with the code. The system calculates and cites; it does not certify. Every report and every export is printed with REGULATORY VALIDITY: NOT ASSESSED. This is permanent, not a phase-one limitation — compliance is asserted by the responsible engineer, and the tool exists to hand that engineer organised work to review.
  • It does not search for the optimal ramp and core position. You asked for this at 34:37 in the meeting and it was the largest request made. It is a search across thousands of arrangements and needs a phase of its own. This version produces a valid layout; it does not hunt for the best one.
  • It does not produce internal unit layouts. No room or bathroom plans. That is a separate product.
  • No Autodesk APS integration, and no live Revit link. APS is a paid Autodesk subscription and a separate integration, so it is out. IFC is not — it is an open ISO standard that Revit imports natively and that needs no subscription, so it has been moved into the scope above. What is excluded is the two-way link: the model travels as a file, and changes made in Revit do not come back.
  • Not the whole 843-page code. Parking, setback, dimension and access clauses are coded. The rest is not.
  • No fire or life-safety assessment. The 707-page UAE Fire Code, travel distances and egress are not assessed — and they are listed as deferred in every output rather than omitted, because a missing check reads as a check that passed.
  • Other developers' standards — Emaar, Damac, Nakheel. Not a technical limit and not a subscription: we simply do not have those documents. Azizi is built as the working model, and adding another is data entry once its brief is in hand.
  • Automatic RFP extraction, plot drawing on a map, user management, mobile app. All buildable without a subscription, none of them in a seven-day window. Listed as extensions on the next page.

Honest note on the timeline and the price

One week is enough because the calculation engine already exists and is tested. Starting from zero, this is months of work, not days. What is delivered at the end of the week is a working version you can demonstrate — precisely what you asked for at 09:58: something boxed you can show someone. It is not a production system a team runs on daily; that is the phase after this one.
